# สรุปการดำเนินงาน ปัญหา และการแก้ไข: โครงการสอนโมเดลภาษาอังกฤษให้เข้าใจภาษาไทย (Task 1)

เอกสารนี้รวบรวมประวัติการดำเนินงานทั้งหมด ตั้งแต่จุดเริ่มต้น ปัญหาที่พบในแต่ละขั้นตอน แนวคิดเบื้องหลังการแก้ปัญหา จนถึงการค้นพบข้อผิดพลาดล่าสุด และแนวทางแก้ไข เพื่อให้เป็นบันทึก (Log) สำหรับการทำงานต่อไป

---

## 1. จุดเริ่มต้นและเป้าหมาย (The Objective)
**เป้าหมายหลัก:** ต้องการนำโมเดล **SapBERT** (โมเดลการแพทย์ที่เป็นภาษาอังกฤษ) มาปรับจูน (Fine-tune) เพื่อใช้กับงานวิเคราะห์ชื่อเฉพาะทางคลินิก (Clinical NER) ในภาษาไทย 
**ปัญหาตั้งต้น:** โมเดล SapBERT ไม่มีคำศัพท์ภาษาไทยในตัว (Tokenizer ไม่รู้จัก) ทำให้เมื่อป้อนข้อความภาษาไทย โมเดลจะมองเห็นเป็น Unknown Tokens (`[UNK]`) หรือสับเป็นตัวอักษรย่อยๆ ทำให้ไม่สามารถวิเคราะห์บริบทได้

---

## 2. การดำเนินการและปัญหาในแต่ละระยะ (Phases & Challenges)

### Phase 1: การขยายคำศัพท์ (Vocabulary Expansion)
- **สิ่งที่เราทำ:** สร้างสคริปต์ `scripts/extend_tokenizer.py` เพื่อเพิ่มคำศัพท์ภาษาไทยที่พบบ่อยจำนวน 20,000 คำ (สกัดจาก Wikipedia และ Lexitron) เข้าไปใน Tokenizer ของโมเดล พร้อมกับเพิ่มตัวอักษรไทยเดี่ยวๆ เป็น Fallback เพื่อกำจัดปัญหา `[UNK]` แบบ 100%
- **ผลลัพธ์:** Tokenizer สามารถตัดคำภาษาไทยได้อย่างถูกต้อง (เช่น `"โรงพยาบาล"` กลายเป็น 1 token แทนที่จะถูกหั่นยิบย่อย)
- **การปรับโมเดล:** เราได้รัน `model.resize_token_embeddings(len(tokenizer))` เพื่อขยายขนาด Layer ของโมเดลให้รองรับคำศัพท์ 20,000 คำนี้ (น้ำหนักของคำเหล่านี้ถูกสร้างขึ้นมาใหม่แบบสุ่ม - Random Initialization)

### Phase 2: พยายามสอนภาษาไทยด้วยพจนานุกรม Lexitron (First MLM Pre-training)
- **สิ่งที่เราทำ:** เนื่องจากโมเดลได้คำศัพท์ใหม่ไปแต่ยัง "ไม่รู้ความหมาย" เราจึงใช้เทคนิค **Masked Language Modeling (MLM)** (การทายคำที่หายไปในช่องว่าง) เพื่อสอนโครงสร้างภาษา
- **ชุดข้อมูลแรก (Lexitron):** นำฐานข้อมูลพจนานุกรม Lexitron มาสร้างประโยคฝึกสอน (130,000 ประโยค)
- **เทคนิคที่ใช้:** ใช้เทคนิค **LoRA (Low-Rank Adaptation)** เพื่อประหยัดทรัพยากร โดยแช่แข็ง (Freeze) โมเดลหลัก และเทรนแค่น้ำหนักส่วนเสริมขนาดเล็ก (ตั้งค่า `r=8` ในตอนแรก และปรับเป็น `r=32` เพื่อเพิ่มความจุ)
- **🚨 ปัญหาที่พบ (Overfitting to Dictionary Format):** 
  โมเดลเรียนรู้จาก Lexitron ดีเกินไป แต่ Lexitron เป็นรูปแบบพจนานุกรม (เช่น "คำว่า... หมายถึง...", หรือมีตัวเลข "1. ... 2. ...") ทำให้โมเดลจดจำ **แพทเทิร์นของพจนานุกรม** แทนที่จะเป็นภาษาไทยธรรมชาติ เมื่อทดสอบ Inference โมเดลจึงมักจะทายคำตอบเป็นตัวเลข (1, 2, 3) หรือเครื่องหมายวรรคตอน มากกว่าจะเป็นคำศัพท์ที่มีความหมาย

### Phase 3: การเพิ่มข้อมูล Wikipedia (Corpus Expansion)
- **สิ่งที่เราทำ:** เพื่อแก้ปัญหาการท่องจำแพทเทิร์นพจนานุกรม เราตัดสินใจนำบทความจาก **Thai Wikipedia** เข้ามาผสม เพื่อให้โมเดลได้เห็นประโยคภาษาไทยที่ต่อเนื่องและเป็นธรรมชาติ
- **🚨 ปัญหาที่พบ (Dataset Download Failure):** 
  สคริปต์ `build_wiki_corpus.py` พังเนื่องจาก Dataset `wikipedia` มาตรฐานบน HuggingFace ลิงก์ไปยังเซิร์ฟเวอร์ Wikimedia Dump ที่ถูกลบไฟล์ทิ้งไปแล้ว
- **การแก้ไข:** เปลี่ยนไปใช้ Dataset `wikimedia/wikipedia` (เวอร์ชัน 20231101.th) แทน ซึ่งทำงานได้สำเร็จ ได้ข้อมูลมาทั้งหมดประมาณ 159,719 บทความ นำมาหั่นเป็นประโยคย่อยๆ ได้ **2.32 ล้านประโยค**
- **ผลลัพธ์:** เมื่อนำมารวมกับ Lexitron และสับไพ่ (Shuffle) ใหม่ เราได้ชุดข้อมูลฝึกสอนรวม **2.46 ล้านประโยค** ซึ่งใหญ่และสมบูรณ์แบบมาก

### Phase 4: ปริศนาค่า Perplexity ลดลง แต่ทายคำผิด (The Frozen Embedding Bug)
- **สิ่งที่เราทำ:** ทำการเทรน LoRA ด้วยชุดข้อมูล 2.46 ล้านประโยค (ใช้เวลาหลายชั่วโมง) ผลประเมินออกมาดีมาก ค่า Perplexity ลดลงจาก 407,962 เหลือเพียง **3,960** (แปลว่าความงุนงงของโมเดลลดลงมหาศาล)
- **🚨 ปัญหาที่พบ (Frozen New Embeddings):** 
  เมื่อรัน `test_inference.py` ทดสอบการเติมคำในช่องว่าง `[MASK]` โมเดลยังคงทายออกมาเป็น `['2', '3', '1', '-', ':']` แทนที่จะเป็นคำศัพท์ภาษาไทย (ทั้งที่ความแม่นยำทางสถิติดีขึ้นมาก)
- **🔍 วิเคราะห์หาสาเหตุเชิงลึก:** 
  เราค้นพบว่าโดยปกติ **PEFT (LoRA)** จะทำการ **Freeze น้ำหนัก (Weights) พื้นฐานทั้งหมดของโมเดล** และยอมให้เทรนเฉพาะ Attention Layers (Query, Key, Value) 
  ปัญหาคือตอนเราทำ Phase 1 เราใส่คำไทยเข้าไป 20,000 คำ ซึ่งน้ำหนักของมันเป็น **ค่าสุ่ม (Random)** เมื่อเลเยอร์ `word_embeddings` และ `cls.predictions` (หัวทำนายผล) ถูก Freeze ทำให้ **โมเดลไม่สามารถเรียนรู้หรืออัปเดตน้ำหนักของคำภาษาไทย 20,000 คำใหม่นี้ได้เลยตลอดการเทรน** 
  โมเดลจึงต้องพยายามลดค่า Loss โดยการพ่น "คำเก่าที่มันรู้จักอยู่แล้ว" (เช่น ตัวเลขและสัญลักษณ์) ออกมาแทน

### Phase 5: การแก้ไขปัญหา ณ ปัจจุบัน (The Fix)
- **การแก้ไข:** เข้าไปปรับแก้โค้ดใน `configs/lora_config.yaml` และ `src/models/lora.py` โดยเพิ่มพารามิเตอร์ `modules_to_save` เข้าไปใน `LoraConfig`
  ```yaml
  modules_to_save:
    - "word_embeddings"
    - "cls.predictions"
  ```
- **ผลของการแก้ไข:** คำสั่งนี้จะบอกให้ LoRA **ปลดล็อก (Unfreeze)** เลเยอร์ที่เป็นตารางคำศัพท์และหัวทำนายผล เพื่อให้โมเดลสามารถอัปเดตและเรียนรู้ความหมายของคำภาษาไทย 20,000 คำที่เพิ่งเพิ่มเข้าไปได้

## 3. ขั้นตอนถัดไป (Next Steps)
เนื่องจากการเทรนในรอบก่อนหน้านี้ เลเยอร์คำศัพท์ถูกล็อกไว้ โมเดลจึงยังไม่สมบูรณ์ เราจำเป็นต้อง:
1. **Retrain MLM:** รันคำสั่งเทรนโมเดลใหม่อีกครั้ง (`python scripts/train_lora_mlm.py`) เพื่อให้น้ำหนักของคำศัพท์ภาษาไทยถูกอัปเดตจริงๆ
2. **Merge Model:** รัน `python scripts/merge_lora.py` เพื่อรวมร่างโมเดล
3. **Inference Test:** รัน `python scripts/test_inference.py` เพื่อยืนยันว่ารอบนี้โมเดลทายคำออกมาเป็นภาษาไทยได้อย่างสมบูรณ์ (เช่น ทายคำว่า "รักษา", "ประชาชน" แทนการทายตัวเลข)
4. **NER Fine-tuning:** เมื่อแน่ใจว่าโมเดลอ่านภาษาไทยออกแล้ว ให้นำโมเดลที่ Merge แล้วไปใช้เป็น Base Model สำหรับการเทรนงาน NER (เป้าหมายสูงสุด) ต่อไป

## 4. วิเคราะห์เจาะลึกปัญหาที่พบ (Deep Dive into Encountered Issues)

เพื่อให้เป็นกรณีศึกษา (Case Study) สำหรับการปรับจูนโมเดลข้ามภาษา (Cross-lingual Fine-tuning) ในอนาคต นี่คือรายละเอียดเชิงลึกของปัญหาหลักๆ ที่เราเผชิญและวิธีเอาชนะพวกมันครับ:

### 4.1 ปัญหา Overfitting กับโครงสร้างพจนานุกรม (Dictionary Pattern Overfitting)
- **อาการที่พบ:** เมื่อนำโมเดลไปทดสอบ Inference (เช่น เติมคำใน `[MASK]`) โมเดลกลับทายคำตอบเป็นตัวเลข (1, 2, 3), เครื่องหมายขีด (-), หรือวงเล็บ แทนที่จะทายคำศัพท์ภาษาไทยที่มีความหมายตามบริบท
- **สาเหตุเชิงลึก:** ชุดข้อมูล Lexitron ที่เราใช้ในตอนแรก (130,000 ประโยค) เป็นข้อมูลที่สกัดมาจาก "พจนานุกรม" ซึ่งมีรูปแบบโครงสร้างที่ตายตัวมากเกินไป เช่น `1. ความหมายที่หนึ่ง...`, `2. ความหมายที่สอง...`, หรือ `คำว่า [คำศัพท์] หมายถึง...`
  เมื่อใช้ข้อมูลแบบนี้เทรนด้วยวิธี MLM (สุ่มเจาะรู 15% ของประโยค) โมเดลเรียนรู้ว่าสถิติความน่าจะเป็นที่สูงที่สุดในการเติมคำในช่องว่างหน้าประโยคคือ "ตัวเลข" หรือ "สัญลักษณ์" โมเดลไม่ได้เรียนรู้ความหมายของภาษา แต่ไปจำ "โครงสร้างหน้ากระดาษพจนานุกรม" แทน (Overfitting to Structure)
- **วิธีแก้:** ต้องเจือจางโครงสร้างนี้ด้วยข้อความที่มีความเป็นธรรมชาติสูง (Natural Language) เราจึงดาวน์โหลดบทความจาก Wikipedia ภาษาไทยกว่า 150,000 บทความ (สร้างประโยคได้ 2.3 ล้านประโยค) มาผสมเข้าไป ทำให้สัดส่วนประโยคธรรมชาติสูงกว่าประโยคพจนานุกรมถึง 17 เท่า (94% vs 6%) บังคับให้โมเดลเลิกจำตัวเลขและหันมาวิเคราะห์บริบททางภาษาแทน

### 4.2 ปัญหาลิงก์ฐานข้อมูลตาย (Dead Dataset Links on HuggingFace)
- **อาการที่พบ:** สคริปต์ `build_wiki_corpus.py` ค้าง และแจ้ง Error ว่าไม่สามารถเชื่อมต่อ หรือไม่พบไฟล์ ZIP ของ Wikipedia ได้
- **สาเหตุเชิงลึก:** ปกติแล้วนักพัฒนามักจะเรียกใช้ `load_dataset("wikipedia", "20220301.th")` แต่ระบบเบื้องหลังของ HuggingFace จะวิ่งไปโหลดไฟล์ Dump (Backup) ตัวจริงจากเซิร์ฟเวอร์ของ Wikimedia ซึ่งทาง Wikimedia มีนโยบายลบไฟล์เก่าทิ้งเป็นประจำ ทำให้ลิงก์ขาด (Broken Links) อยู่เสมอ
- **วิธีแก้:** เราเปลี่ยนไปใช้ Dataset ชื่อ `wikimedia/wikipedia` (เวอร์ชัน `20231101.th`) แทน ซึ่งเป็น Repository อย่างเป็นทางการที่ทาง Wikimedia นำไฟล์ Dump มาฝากไว้บน Cloud Storage ของ HuggingFace โดยตรง ทำให้ไฟล์ไม่มีทางโดนลบทิ้งและโหลดได้อย่างเสถียร 100%

### 4.3 ปัญหาภัยเงียบของ LoRA กับตารางคำศัพท์ใหม่ (The "Frozen New Token" Trap)
- **อาการที่พบ:** แม้ว่าจะเทรนด้วยข้อมูล 2.4 ล้านประโยคจนค่า Perplexity (ความงุนงง) ลดลงจาก 4 แสนเหลือเพียง 3 พัน แต่เวลาทายผล โมเดลก็ยังดึงดันที่จะทายคำตอบเป็นตัวเลขหรือสัญลักษณ์อยู่ดี (ไม่มีคำภาษาไทยโผล่มาใน Top 5 เลย)
- **สาเหตุเชิงลึก (เรื่องนี้สำคัญมาก):** 
  เรามีการขยายขนาด Tokenizer โดยเพิ่มคำศัพท์ภาษาไทยเข้าไป 20,000 คำ (`resize_token_embeddings`) ส่งผลให้น้ำหนัก (Weights) ของคำศัพท์ใหม่เหล่านี้ถูกสร้างขึ้นแบบ "สุ่ม" (Random Initialization)
  ต่อมาเมื่อเราใช้ **PEFT (LoRA)** ในการเทรน พฤติกรรมดั้งเดิม (Default) ของ LoRA คือการ **แช่แข็ง (Freeze)** เลเยอร์พื้นฐานทั้งหมดของโมเดล และยอมให้เราเทรนเฉพาะ Attention Matrix (`query`, `key`, `value`) 
  **ผลที่ตามมาคือ:** น้ำหนักแบบสุ่มของคำศัพท์ภาษาไทย 20,000 คำนั้นถูก "แช่แข็งไว้อย่างถาวร!" โมเดลไม่สามารถปรับจูนน้ำหนักเหล่านี้ให้เข้าใกล้ความหมายที่แท้จริงได้เลยในระหว่างการเทรน เมื่อโมเดลไม่มีทางเลือก (มันใช้คำไทยไม่ได้เพราะ Weights พัง) มันจึงต้องคายคำเก่าๆ ที่มันรู้จักน้ำหนักดีอยู่แล้ว (เช่นตัวเลขและสัญลักษณ์) ออกมาแทนเพื่อลดค่า Loss ให้มากที่สุดเท่าที่จะทำได้
- **วิธีแก้:** ต้องเข้าไปแก้ Config ของ LoRA โดยเพิ่มคำสั่ง `modules_to_save: ["word_embeddings", "cls.predictions"]` เพื่อบังคับให้ PEFT **ปลดล็อก (Unfreeze)** ตารางคำศัพท์และหัวทำนายผล (LM Head) ให้น้ำหนักของคำศัพท์ใหม่ๆ สามารถเรียนรู้และถูกอัปเดตไปพร้อมๆ กับตัว LoRA Adapter ได้

### 4.4 ปัญหาข้อความเตือนของไลบรารี (Deprecation Warnings & Environments)
- **อาการที่พบ:** ระหว่างรันสคริปต์ มักพบข้อความแจ้งเตือนสีแดงยาวๆ เช่น `no_cuda is deprecated` หรือพยายามเชื่อมต่อเน็ตเพื่อส่ง Log ไปที่ TensorBoard/WandB
- **สาเหตุและวิธีแก้:** 
  1. `TrainingArguments` ใน Transformers เวอร์ชันใหม่ๆ ยกเลิกการใช้คำสั่ง `no_cuda=True` เราจึงแก้ไขโค้ดให้ใช้ `use_cpu=True` แทนเพื่อหลีกเลี่ยง Error

## 5. 🛠️ บันทึกการแก้โค้ดก่อน Retrain (Code Fixes — 2026-09-07)

หลังจากรีวิวโค้ดทั้งหมด พบบัคเพิ่มเติมที่ต้องแก้ก่อน retrain (ดู `CLAUDE.md` ข้อ 5 — Checklist) และได้ดำเนินการแก้แล้วดังนี้:

### 5.1 Smart Init Bug (Circular Initialization) — `scripts/extend_tokenizer.py`

**ปัญหา:** ฟังก์ชัน `smart_init_embeddings()` ถูกเรียกด้วย tokenizer **ตัวใหม่** (ที่ reload จาก vocab.txt ใหม่แล้ว) ทำให้เมื่อ tokenize คำไทยใหม่ เช่น "โรงพยาบาล" → ได้ token เดียวคือ ID ของตัวมันเอง → mean ของ embedding ตัวมันเอง (ซึ่ง ณ จุดนั้นเป็นค่า random จากการ resize) = ค่า random เท่าเดิม **ไม่มีผลอะไรเลย**

**สาเหตุ:** ลำดับเวลาผิด — comment ในโค้ดเขียนว่า *"Tokenize the new token with the OLD vocab"* แต่โค้ดจริงรันหลัง tokenizer ถูก replace ไปแล้วด้วย `BertTokenizer.from_pretrained(str(output_dir))`

**การแก้ไข:**
- เพิ่มขั้นตอน capture `decomposition` (mapping: คำไทย → list of OLD subword IDs) ด้วย **tokenizer ตัวเก่า** ก่อนถูก reload ทับ
- ส่ง mapping นี้เข้า `smart_init_embeddings()` แทนการ tokenize ใหม่
- ฟังก์ชันใหม่กรอง `[UNK]` ออก, คำนวณ mean จาก subword embeddings เดิมที่เทรนแล้วจริง
- ถ้า decomposition เป็น `[UNK]` ทั้งหมด → ใช้ UNK embedding เป็น fallback (ดีกว่า random เพราะเป็น trained vector)
- Log สรุปจำนวน: init จาก subwords / UNK fallback / skipped

**ผลลัพธ์:** คำไทย 20,000 คำจะได้ embedding เริ่มต้นจาก mean ของ subwords เดิมจริง (ไม่ใช่ random) → การเทรน MLM เรียนรู้เร็วขึ้นและดีขึ้น

### 5.2 TaskType Hardcode — `src/models/lora.py`

**ปัญหา:** `apply_lora()` hardcode `task_type=TaskType.FEATURE_EXTRACTION` เสมอ โดยไม่อ่านค่าจาก `configs/lora_config.yaml` (field `task_type`) → ถ้าอนาคตใช้กับ NER config (`task_type: TOKEN_CLS`) จะได้ PEFT model ที่ task type ผิด (silent bug — ไม่ error แต่ทำงานผิด)

**การแก้ไข:** อ่าน `task_type` จาก `lora_cfg` ผ่าน `getattr(TaskType, task_type_str)` พร้อม error handling ถ้าชื่อไม่ valid (แสดง list ของ TaskType ที่ใช้ได้ทั้งหมด)

### 5.3 Hardcoded Absolute Path — `scripts/extend_tokenizer.py` + `configs/model_config.yaml`

**ปัญหา:** default ของ `--source-model` เป็น path Linux `/home/aom/NECTEC/NER/outputs/models/SapBERTThaiMLM_CRF` → ย้ายมา Windows (`I:\`) แล้วรันไม่ได้
